## 现有功能深化（2026-10-25）

- 每日行程：拖动把手排序/跨天移动，保留原有按钮操作；撤销最近一次行程修改，版本冲突时拒绝覆盖。设置每日出发时间、每站前交通和游览后休息，随当前顺序重算时间，超过午夜时提醒。时间由用户填写与编辑建议组成。
- 景点—美食—预算：景点详情展示同城美食和公开路线；从美食选择个人行程、日期、餐次、同城关联景点及预计餐费。明确确认后计入预算，同一计划重复同步更新同一笔费用并保留实际支出。移除用餐计划不自动删费。
- 预算深化：费用可关联日期/景点，按天统计，分类计划与实际对比，点击日期/分类筛费用明细。缩短天数或移除景点后，旧费用保留并提示失效关联，可重新安排。
- 推荐调整：保留指定站点及日期、替换单站、暂不考虑/恢复景点、重新组合其余安排。候选不足时明确提示，取消勾选的景点不会保存。
- 公开路线：收藏与复制分开，个人路线收藏入口；按天展示缩略图、停留时长。源行程景点/日期/天数变化时，提示公开版本待更新；只修改私人备注不会误报。
- 足迹深化：逐站感想和每站一张私人照片，按账号归属读取。仅选择的文字生成游记草稿，可继续编辑并确认公开，照片和预算不会自动进入社区。
- 内容维护：后台列出缺封面、资料来源、建议时长、关联景点等实际缺项，直接进入原编辑弹窗；检查结果是编辑建议，不自动下架。
- TXT 清单包含时间、用餐计划和费用关联。预算、时间、用餐和足迹均只向本人开放。

## 持久化版本历史（2026-10-25）

行程页“版本历史”弹窗提供倒序分页、完整旧版预览、任选两版差异和确认恢复。名称、天数、出发日期、行程/逐站备注、景点日期顺序、清单和每日出发/交通/休息时间进入快照。恢复会生成新的 RESTORE 版本，旧版继续保留。预算、用餐计划、足迹和公开路线独立保存，恢复后可自行检查关联日期。

技术实现：trip_versions 保存不可变 JSON 快照、类型、摘要、来源版本和两个实际版本号。创建/修改行程、修改时间和复制路线时，在原事务中捕获快照；内容无变化不重复记录。已有行程首次升级只记录当前安排为 BASELINE，不追溯不存在的旧修改。再次启动不重复基线。

恢复同时检查当前行程 revision、每日时间 revision 和 history_version；随后复用原行程校验，并在同一事务中写回核心安排、每日时间和恢复记录。任意一步失败全部回滚。历史景点已下架且已从当前行程移除时，整份拒绝恢复；当前仍保留的下架景点可保留。历史仅本人可访问，管理员不能越权读取；删除行程级联删除历史，复制公开路线只建立副本自己的 CREATE 版本。

差异按基本资料、增加/移除景点、日期顺序、逐站备注、清单和时间分别计算；新增/删除日期的出发时间也会显示。对比选择跨页保留。长内容弹窗只有内容区滚动；关闭、切页、换账号后旧请求不能回填。登录或令牌刷新确认会话失效时关闭私人弹窗、清理行程缓存并显示登录入口。

体验账号 traveler 的“南阳两日游（功能体验）”（/trip/30）保留三份实际操作产生的记录：当前安排基线、移动景点并修改备注、恢复版本 1 后的新版本 3。当前安排已恢复，费用和用餐保留，没有新增虚构足迹或社区帖子。

新增源码：TripVersions.java、TripVersionController.java、trip-versions.js/css；新增表见 sql/trip-versions.sql，已合入完整 sql/schema.sql。历史会增加数据库体积；停止网站后备份整个 data/ 目录，sql/guide.db 是固定演示初始库。

## 带约束的行程规划（2026-10-25）

入口 /planner，也可从快捷推荐、我的行程和行程页进入。单次针对一个目的地，支持 1～7 天、最多 18 个候选景点。每一天设置最早出发和最晚结束，候选可设置必去、固定到某一天、兴趣 1～5、到达前交通 0～240 分钟及游览后休息 0～180 分钟。固定日期同时视为必去。游览时长使用当前编辑建议，交通休息由用户估计，首站交通和末站休息也计入时限，不推断实时路况和开放时间。

ConstraintPlanner 为无数据库/网络依赖、输入确定的 Java 规划核心。先预检单个必去、固定日期合计、必去总量等硬冲突；再对必去做有界回溯（最多 50,000 节点、64 个种子），对可选项作宽度 256 的束搜索扩充。穷尽且无解、达到搜索上限尚未找到解分开返回。最多提供三份不同可行候选；不声称全局最优。搜索截断会在元数据中标记。

兴趣效用为每站 20×兴趣等级，加主题匹配 15；在效用基础上，均衡模式倾向缩小每天时段利用率差，集中模式倾向减少活动日期，兴趣模式进一步偏向主题匹配。结果展示逐站到离时间、每日总时长与剩余分钟、选择理由和未入选原因；修改条件立即使旧预览失效。

匿名可预览，保存需要登录且可接着原操作继续。服务端使用规范化条件与当前景点资料的 SHA-256 指纹，保存时重新求解，忽略客户端伪造的结果。资料变化会要求重新生成。每次保存创建新的私人行程，不覆盖旧行程；核心安排、时间、规划条件、CREATE 历史和保存编号在同一事务中写入。user_id+request_key 幂等键在事务首条写语句占位，重复并发请求返回同一行程；同编号不同内容拒绝。

行程页保留规划条件及当前复核：必去是否移除、固定日期是否偏离、出发是否过早、结束是否超时、是否跨出原城市或遇到下架。手动编辑或历史恢复后按当前数据重新检查；重新规划读取原条件并生成另一份行程。预算、用餐、足迹、公开路线仍分别保存。公开路线副本不携带原私人规划条件。

新增 ConstraintPlanner.java、ConstraintPlannerController.java、constraint-planner.js/css；planning_constraints、planner_saves 两表见 sql/constraint-planner.sql，已并入全量脚本。算法独立检查源码与运行方法在 tests/。

## 中文全文搜索（2026-10-26）

景点与攻略搜索升级为 SQLite FTS5 倒排索引。支持中文单字、短词、连续短语及多个关键词组合；空格或标点分隔的关键词必须全部命中，可分别位于地区、标题、简介和正文。拉丁文字按完整词匹配，统一大小写与全半角。无关键词时保留原有公开列表、筛选和收录顺序。

景点覆盖介绍、看点、交通、提示；攻略覆盖副标题、小节标题与全部正文。结果默认使用加权 BM25 相关度，标题 8、地区 5、简介 3、正文 1；可切回收录顺序。结果显示命中位置、原文高亮和命中附近的正文摘要。地区、主题、时长及分页继续生效。仅对景点与攻略提供本轮全文搜索，社区、美食和路线仍使用各自的原有搜索。

后台新增、修改、上下架及地区更名会自动标记索引待更新，下次关键词搜索在同一个事务内更新并查询；删除内容会移除索引。读取公开结果时再次核对 published。不会索引私人行程、预算、账号、评论或反馈。搜索词不写入用户搜索历史。

新增 SearchText.java、SearchIndex.java、SearchController.java、fulltext-search.js/css；sql/fulltext-search.sql 已合入完整建表脚本。启动时首次构建，之后只更新待处理内容。实现细节与边界见 docs/fulltext-search.md。
