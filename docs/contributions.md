# 用户投稿与管理员审核

普通用户可在个人中心的“我的投稿”补充景点、分享攻略和推荐地方美食，也可以从资料详情页发起“纠错 / 补充资料”。目的地城市仍由管理员维护。

## 操作流程

1. 编辑内容，保存为草稿。草稿允许暂时不完整。
2. 提交审核时检查必填资料、图片、城市、攻略关联景点和资料链接。
3. 待审核期间不能编辑，可先撤回再修改。
4. 管理员在“后台管理 → 投稿审核”查看内容、原资料对照和历史审核说明，选择“通过并发布”或填写理由后“退回修改”。
5. 退回后作者可修改并重新提交；已通过的投稿作为历史记录保留，再次补充需发起新的修改建议。

新增资料审核通过后进入现有景点、攻略或美食库，使用原有详情页与检索入口。修改建议通过后更新原资料，不另建重复资料。

## 权限与一致性

- 作者只可读取和操作自己的投稿，普通用户无审核权限。
- 修改建议由服务器保存发起时的原资料快照和版本。原资料发生变化时，审批返回冲突；作者需要更新对照版本，再重新提交。更新对照版本保留已保存的建议内容。
- 已下架的资料或城市不能通过旧投稿重新发布；攻略关联景点必须仍公开且属于同城。
- 审核中的公开内容写入、投稿状态、审核历史和管理员操作记录处于同一数据库事务。重复操作或同时审核只能成功一次。
- 未通过内容不进入公开列表或全文索引。通过后沿用现有检索触发器更新索引。

## 图片与备份

投稿图片仅接受 5 MB 以内的 JPG、PNG，检查真实图像格式与像素上限，并转为最长边不超过 1600 像素的 JPEG。未审核图片位于 `data/contribution-uploads/`，通过受保护的接口读取，只有上传者和管理员能访问。

批准时把引用的私人投稿图片转存为公开图片；转存或数据库写入失败时回滚发布并清理新副本。原私人图片地址仍保持访问限制。每账号最多保留 100 个未完成草稿、上传 100 张投稿图片。

备份应保存整个运行数据目录，包括数据库、公开图片、私人行程照片和投稿图片。现有停站备份工具递归备份该目录，包含新增的投稿图片目录。不要只复制 `guide.db`。

## 数据初始化

新增表为 `contributions`、`contribution_reviews`、`contribution_images`，独立脚本为 `sql/contributions.sql`。主 schema 也包含这些表；启动时以 `IF NOT EXISTS` 安全创建，已有用户与旅行资料不重新导入。`sql/guide.db` 保持固定演示初始库，运行库使用启动配置指定的数据目录。

## 集成检查

`tests/verify_contributions.py` 只能对项目 `work/` 下的隔离运行库执行，需显式提供 `ROAM_BASE`、`ROAM_DATA_DIR`、`ROAM_QA_DB`，拒绝默认正式端口 8818 和正式数据目录。测试会创建自己的账号和资料，检查权限、状态转换、发布检索、版本冲突、并发审核、图片保护及事务故障回滚，并清理本轮测试记录。
