# 用户投稿与管理员审核

普通用户可在个人中心的“我的投稿”补充景点、分享攻略和推荐地方美食，也可以从资料详情页发起“纠错 / 补充资料”。目的地城市仍由管理员维护。

## 操作流程

1. 编辑内容，保存为草稿。草稿允许暂时不完整。
2. 点击“预览并提交”，先保存当前输入，再查看按详情页排版生成的私人预览。检查通过后，点击“确认提交审核”。未完成的草稿仍可预览，并提示需要补充的资料。
3. 待审核期间不能编辑，可先撤回再修改。
4. 管理员在“后台管理 → 投稿审核”查看内容、原资料对照和历史审核说明，选择“通过并发布”或填写理由后“退回修改”。
5. 退回后作者可修改并重新提交；已通过的投稿作为历史记录保留，再次补充需发起新的修改建议。

审核通过或退回时，消息中心会收到个人通知，可直接打开对应投稿。通知与审核结果在同一事务中保存，审核失败或重复操作不会留下多余通知。

编辑后会在短暂停顿时自动保存，并显示保存进度；仍可使用手动保存按钮。提交审核前会保存最新内容。出现版本冲突时停止自动保存并提示重新加载，避免覆盖另一标签页的更新。

预览由服务器按已保存版本生成，图片、正文和攻略关联景点均来自同一份草稿快照；返回编辑保留输入。确认提交绑定预览时的版本，另一标签页修改后须重新加载并生成预览。读取预览不改变审核状态、不发布图片、不发送通知，也不写入公开检索；无效或已下架的关联资料使用占位提示。

## 公开署名与时间

景点、攻略和美食详情显示内容署名。用户新增资料审核通过后显示原投稿者，后续补充保留原署名并显示最近贡献者；原有编辑资料显示“漫游编辑整理”。管理员账号和审核说明不会成为公开署名。

时间来自已有记录：原有资料显示“收录于”，用户新增内容显示真实审核发布日，后续成功审核或后台编辑才显示“更新于”。未提交、待审核和退回的修改不会改变公开时间；不会把升级当天写成旧资料的更新时间。署名信息与公开正文在同一读取事务中取得。

草稿及“需修改”的投稿可移入回收站，保留内容和审核说明，恢复后继续编辑。待审核投稿须先撤回；已通过投稿作为历史保留。回收站不会自动清空，永久删除需明确确认。回收站中的草稿不占活跃草稿限额，恢复时重新检查容量。

新增资料填写标题和城市后，会提示同城同类的公开资料中可能重复的内容。可以查看已有资料、将当前内容保存为草稿后改为补充，也可以继续新增。匹配只作提醒，不保证找出所有重复内容，不检查其他用户的私人草稿。

新增资料审核通过后进入现有景点、攻略或美食库，使用原有详情页与检索入口。修改建议通过后更新原资料，不另建重复资料。

## 权限与一致性

- 作者只可读取和操作自己的投稿，普通用户无审核权限。
- 修改建议由服务器保存发起时的原资料快照和版本。原资料发生变化时，审批返回冲突；作者需要更新对照版本，再重新提交。更新对照版本保留已保存的建议内容。
- 已下架的资料或城市不能通过旧投稿重新发布；攻略关联景点必须仍公开且属于同城。
- 审核中的公开内容写入、投稿状态、审核历史和管理员操作记录处于同一数据库事务。重复操作或同时审核只能成功一次。
- 未通过内容不进入公开列表或全文索引。通过后沿用现有检索触发器更新索引。

## 图片与备份

投稿图片仅接受 5 MB 以内的 JPG、PNG，检查真实图像格式与像素上限，并转为最长边不超过 1600 像素的 JPEG。未审核图片位于 `data/contribution-uploads/`，通过受保护的接口读取，只有上传者和管理员能访问。

批准时把引用的私人投稿图片转存为公开图片；转存或数据库写入失败时回滚发布并清理新副本。原私人图片地址仍保持访问限制。每账号最多保留 100 个未完成草稿、上传 100 张投稿图片。

“图片整理”显示本人的投稿图片及引用状态。只有未被任何本人投稿内容或原资料快照引用的图片才能删除；回收站与已通过历史中的引用也会阻止删除。先移除稿件中的引用或永久删除回收站稿件，再清理不需要的图片。删除图片需要确认，并会释放上传名额。图片删除和草稿保存采用同一数据库写锁协调，防止一边引用、一边删除造成断图。

备份应保存整个运行数据目录，包括数据库、公开图片、私人行程照片和投稿图片。现有停站备份工具递归备份该目录，包含新增的投稿图片目录。不要只复制 `guide.db`。

## 数据初始化

新增表为 `contributions`、`contribution_reviews`、`contribution_images`，独立脚本为 `sql/contributions.sql`。主 schema 也包含这些表；启动时以 `IF NOT EXISTS` 安全创建，已有用户与旅行资料不重新导入。`sql/guide.db` 保持固定演示初始库，运行库使用启动配置指定的数据目录。

回收站使用可空的 `contributions.deleted_at` 字段，保留原有四种审核状态。应用启动时检查已有表的列并补充该字段，不重新创建或清空旧表；全量 schema 和新建表脚本也包含此字段。

## 集成检查

`tests/verify_contributions.py` 只能对项目 `work/` 下的隔离运行库执行，需显式提供 `ROAM_BASE`、`ROAM_DATA_DIR`、`ROAM_QA_DB`，拒绝默认正式端口 8818 和正式数据目录。测试会创建自己的账号和资料，检查权限、状态转换、发布检索、版本冲突、并发审核、图片保护及事务故障回滚，并清理本轮测试记录。

`tests/verify_contribution_preview.py` 使用相同隔离限制，覆盖预览只读性、版本冲突、私图保护、三种内容合并、公开署名和时间来源，以及失败审核的回滚。
