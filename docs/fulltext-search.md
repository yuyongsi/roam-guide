# 中文全文搜索实现说明

## 用户体验

搜索入口 /search 与攻略列表 /guides。可尝试“南阳 汉画”“车马”“碑刻”。前两个关键词可分别命中城市与正文；连续输入的中文短语必须在同一字段中连续出现，不跨标点或段落拼接。默认返回相关度最高的结果，支持地区、主题、时长联合筛选及稳定的编号次排序。无输入仍按收录顺序浏览。

每张搜索结果卡片展示命中字段与120个Unicode字符以内的正文摘录（省略号另计），标题、地区和摘录中的匹配内容高亮。返回的是 text/match 结构，前端对每段原文转义后再插入固定 mark 标签，正文中的HTML不会被执行。英文按完整词匹配，不提供拼写纠错、拼音检索、近义词扩展或语义理解。

## 索引与排序

SearchText 统一 NFKC 全半角和小写；每个汉字编码为独立 token，其他连续字母数字编码为一个完整词。token采用带类型前缀的十六进制编码，边界标记与内容词不重名。中文词组转换为 FTS5 带引号的连续短语；多个输入词组以 AND 连接。FTS操作符、引号等输入不会直接拼接成FTS语法，SQL参数另行绑定。最多100个UTF-16字符与12个不同关键词。

search_fts 是真实 FTS5 虚拟表，分 title、intro、body、location 四个索引字段，type/item_id 只作归属信息。查询采用 MATCH 和 bm25(search_fts,8,3,1,5,0,0)，较小值排前，相同分数按内容编号排序。无需额外搜索服务或下载分词词典。这是中文字符短语检索，不声称语言学分词或全局语义相关。

景点正文汇总 description/highlights/transportation/tips；攻略从 sections JSON 只提取每段标题和正文，并加入副标题，避免把JSON键名、资料链接或图片路径作为正文索引。

## 更新一致性与权限

源表INSERT/UPDATE/DELETE触发器在原事务内写入search_dirty，主键type/item_id合并重复通知。城市名称/省份更新会标记所属景点攻略。启动在seed/enrich之后初始化触发器和首次索引；后续只处理待更新条目，不覆盖编辑资料。

关键词查询事务以一条无实际行变更的UPDATE先取得SQLite写锁，再刷新待处理条目、计算总数并读取当前页。这样避免先读后写的锁升级，也避免刷新后源数据变化导致旧词命中新正文；同时只有已发布源记录能够返回。此方式适合本课程本地小型数据集，关键词查询会短暂参与SQLite写锁竞争，不以小样本结果宣称大规模并发能力。

下架/删除待处理行先移除旧索引，仅仍公开的源记录重新写入。所有索引操作与待处理标记删除原子提交。搜索API只输出公开摘要字段及高亮结构，不返回原始完整正文或内部tokens。仅景点与攻略进入此索引，私人行程、预算、反馈、用户与评论均不参与。社区、美食、公开路线的原有栏目检索保持原实现。

## API与部署

GET /api/search 保留 type/q/city/theme/duration/page/size 参数，增加 sort=relevance|editor。旧调用不需要修改。非空纯标点输入返回0条；无关键词不查询倒排索引，按编辑顺序浏览。响应新增 terms、sort、engine 和逐项 search 信息。

源表定义和FTS虚拟表在 src/main/resources/schema.sql；完整触发器单独位于 search-triggers.sql，通过完整CREATE TRIGGER语句执行，避免拆开触发器中的分号。sql/schema.sql包含可独立执行的全量表与触发器。首次启动自动建立索引，sql/guide.db提供检查后的快照。SQLite数据库备份请使用一致性快照，避免只复制正在写入的主文件。

## 验证

39项真实HTTP/SQLite检查覆盖中文单字双字短语、正文检索、组合AND、排序分页、上下架同步、地区更名、删除、完整英文词与全角、特殊字符、并发查询和索引范围。另有421项实际SearchText断言和6项实际前端源码的转义检查。运行方法见 tests/README.md。
