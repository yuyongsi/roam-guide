# 日志与统一报错（2026-10-26）

> 以下为各轮历史验证记录，不代表当前运行状态。当时的“同步”仅描述当次整理；现在 `sql/guide.db` 是固定演示初始库，`data/guide.db` 是独立运行库，不会自动回写。

本轮仅补充公共日志、错误处理和前端请求处理，没有调整原有业务分层、数据库表或页面功能。

## 日志在哪里

默认位于运行数据目录下的 `logs/`：

- `data/logs/runtime.log`：启动信息及服务端异常诊断。
- `data/logs/requests.log`：接口请求及失败页面请求，包含北京时间、等级、请求编号、请求方法、路由模板、HTTP状态、毫秒耗时及会话账号编号。
- `data/logs/archive/`：按日期和大小轮转的 gzip 归档。
- 管理员操作记录继续保存在数据库中，通过管理后台“操作记录”查看，不受文件日志的保留期影响。

每类文件默认单份约5MB滚动、归档保留14天，每类归档按50MB额度清理。Logback的压缩和清理异步执行，活动文件不计入归档额度，滚动期间可能短暂超出额度；不是文件系统硬配额。启动时也会清理过期归档。配置来自 `roam.logging.max-file-size/max-history/total-size-cap`。

可用 `ROAM_DATA_DIR` 指定数据目录，日志随之进入其 `logs/`；也可用 `ROAM_LOG_DIR` 单独指定日志目录。日志是运行产物，不放入最终作业提交包。没有新增在线系统日志下载或浏览接口。

## 如何查一个问题

1. 用户遇到服务异常时，记录提示中的“问题编号”。独立错误页可展开“查看问题编号”。
2. 在 runtime.log、requests.log 或归档中查找这个完整编号。
3. 如果是已接入的后台管理操作，还可在后台操作记录里展开记录编号，与请求日志对应。

所有请求的 `X-Request-ID` 由服务端新建，不信任客户端传来的同名值。API报错返回 `status/code/message/request_id`，管理员审计采用相同的编号。线程上下文在请求结束后清理，避免并发串号。

日志只保留路由模板，例如 `/api/spots/{id}`，不记录查询参数、未匹配的原始网址、请求正文、Cookie、授权头、文件原名、密码或临时密码。服务端异常只记录异常类型与源代码堆栈位置，不记录可能含SQL参数或私人正文的异常消息。请求账号使用会话编号，不记录原始登录用户名。

成功静态资源和普通成功页面不逐条记录，避免图片/CSS/JS访问淹没业务日志；接口请求和失败页面均有记录。拒绝登录、权限、CSRF以及控制器参数解析失败的请求也进入请求日志，但不会伪装成已执行的管理员操作。

## 报错行为

- 业务校验、权限、版本冲突仍沿用原有具体提示。
- 参数转换、JSON错误、缺少参数或上传文件等统一为中文400提示。
- 上传超过5MB返回413；提交格式不支持返回415；请求方法不支持返回405。
- 内容/页面不存在返回404；数据库和未知程序异常返回通用中文500提示，不将堆栈或SQL返回浏览器。
- 浏览器直接打开错误页面时显示独立中文页面，保留真实HTTP状态，提供返回首页、重新加载和问题编号，适配日夜模式。页面不依赖完整应用脚本才能显示。
- `/api/` 请求即使声明希望接收HTML，仍返回统一JSON；独立网页错误采用HTML。错误响应禁止缓存，避免显示旧编号。
- 前端将网络失败、超时、非JSON响应转换为中文提示。普通请求20秒超时，图片上传60秒；服务端尚未返回头部的网络失败没有服务端编号，不编造编号。
- 写入超时提示先刷新确认操作结果，客户端不会自动重试写入。主动取消与超时分开处理，原有登录恢复和私人缓存清理逻辑继续有效。

日志以本地排错为目标，没有引入全天候监控平台、告警服务或浏览器异常遥测。网络断开可能发生在服务器已完成保存之后，因此客户端不能仅凭超时判定保存失败。已经开始传输的响应也不能回头修改HTTP状态；这类异常仍记录诊断与错误级别。

## 测试与证据

修改前只读复现：无效景点编号、错误分页类型和未知页面会落入不同的框架默认格式；错误响应没有统一编号。原有日志仅输出控制台。

最终验证：原15组回归456项、地图/审计85项、只读错误契约4项、日志和报错专项96项，共641项接口/数据库及日志检查通过；另有实际源码请求错误断言12项、表单断言27项、全文搜索UI断言6项、评论排序实际SQL查询4项，共49项通过。

专项验证包括：400/401/403/404/405/409/413/415/500、畸形JSON、HTML与JSON响应、编号关联、SQL故障回滚、未知异常、请求头/正文/异常消息脱敏、实际文件落盘与压缩轮转、历史归档清理、归档额度清理以及数据库完整性。归档测试采用隔离的4KB文件、8KB额度与1天保留期，允许一个活动轮转文件的异步清理余量，并核实旧归档确实被删除。

所有故障注入只在 `work/error-logging-build` 的独立数据库和 `error-qa` 专用测试控制器中进行。该测试控制器只存在于工作区测试副本，不进入交付源码和正式运行包。

浏览器检查了500页面、问题编号展开、重新加载、返回首页及黑夜模式。生产站只做只读检查，不注入服务故障。

参考：[Spring Boot日志配置](https://docs.spring.io/spring-boot/reference/features/logging.html)、[Logback轮转与清理](https://logback.qos.ch/manual/appenders-rolling.html)。
