# 景点地图与后台操作记录（2026-10-26）

> 以下为各轮历史验证记录，不代表当前运行状态。当时的“同步”仅描述当次整理；现在 `sql/guide.db` 是固定演示初始库，`data/guide.db` 是独立运行库，不会自动回写。

## 使用方式

- 景点详情标题旁点击“查看地图”，或从右侧目录进入“地图与到达”。在卡片中点击“在高德地图中查看”，会在新窗口按地点名称检索。
- 管理后台的景点编辑弹窗新增“地图检索地点（可选）”。留空时自动使用省份、城市和景点名。修改标题或地区时，如果原检索地点未同时调整，会清空旧检索条件并重新使用默认值。
- 管理员进入 `/admin?section=audit` 查看操作记录，可按管理员或对象名称、类型、成功/失败、日期组合筛选，每页20条。
- 日期筛选按北京时间计算，包含所选开始和结束日期。记录中显示完整日期和秒数；同一时间按记录编号降序排列。

## 实现与边界

地图使用高德官方 URI 搜索接口：https://developer.amap.com/api/uri-api/guide/search/search 。检索关键词与城市分别编码，目标网址固定为 `https://uri.amap.com/search`，无需配置地图密钥。不保存或推测坐标，不将名称检索伪装成已核实的具体入口；到达位置需在地图结果中核对。外部页面使用 `noopener noreferrer`。

操作记录通过 Spring AOP 统一覆盖后台景点、攻略、城市、美食新增/编辑及发布状态、用户封禁/解封和密码重置、社区与公开路线审核、反馈处理、后台图片上传以及管理员删除评论。记录包括管理员、操作类型、对象编号及名称快照、结果、HTTP状态、固定原因、请求编号和时间。记录只提供管理员读取接口，不提供编辑和删除接口。

成功记录与业务数据库修改共用事务，审计写入失败时业务数据库修改回滚；失败操作在回滚后另行记录。SQLite先取得写锁，避免并发编辑过程中从读事务升级写事务失败。已有乐观锁版本校验继续有效。上传文件属于文件系统，数据库事务回滚不会回滚已经生成的文件；失败上传产生的未引用文件可在后续维护中清理。

只采集白名单后台操作，不记录密码、密码摘要、临时密码、CSRF、Cookie、请求正文、评论正文、反馈正文或私人行程。用户管理中仅保存用户名快照。登录/注册、个人中心、普通用户操作不纳入管理员记录；在请求进入控制器前就被登录、来源、CSRF或格式检查拦截的请求不属于本表执行记录。失败原因使用固定文本，不直接保存异常信息或用户输入。

不补造历史记录。本轮自动化和故障注入只运行于 `work/map-audit-build` 的独立数据库，测试账号、强制失败触发器和测试记录均不导入正式站。
