# 景点与社区路线补齐

完成范围：评论排序、景点扩充、社区与公开路线示例。没有增加地图、后台操作记录等其他模块。

## 现在可以体验什么

- 5个目的地各6个景点，共30个；原22篇攻略、10道美食继续保留。
- 每个新增景点都有对应地点照片、介绍、具体看点、交通提示、主题与建议时长，部分含局部图集。
- 社区12篇帖子：每城2篇提问，另有2篇通用出行经验；每篇2条回复，共24条。6篇有地点配图，其余为文字讨论。配图复用本站授权素材，不表示作者自拍。
- 公开路线10条，每城2条，包括一日与两日组合。原南阳体验路线保留，新增9条。
- 新公开路线有独立的私人源行程，分别属于已有演示账号。源安排标明“路线示例源”，不修改原4份私人行程，也不生成虚构旅行完成记录、预算支出或点赞。
- 评论列表按created_at倒序、id倒序，覆盖攻略评论、我的评论、管理后台与社区回复。增加全局评论时间索引和社区帖子回复时间索引。

景点建议时长只包括参观参考，不推断实时交通、开放或预约。内乡县衙、张衡博物馆等片区的去返需另外计算；大理州博物馆与古城内市博物馆、浙博不同馆区分别说明。

## 内容和样例的边界

景点身份与主题参考官方或机构资料，来源见content-sources.md。23个新增图片文件逐一记录作者、原发布页、拍摄日期及许可，见image-credits.md；只缩放、调整方向与压缩，没有生成或替换地点。

社区及路线是课程演示内容，不代表真实到访、真实用户运营数据或官方推荐线路。帖子以出行打算、问题与一般安排方法为主，不编造商家口碑、到访经历、评分或热度。演示用户来源与密码见demo-community.md。

## 历史数据初始化与升级说明

当前运行库data/guide.db及sql/guide.db均已同步完整内容。现有数据库不要直接覆盖。

若需要在新副本体验完整样例，可在首次启动前把sql/guide.db复制为data/guide.db；图片保留src/main/resources/static/assets/。这份快照不含真实个人资料。

也可以从空库重新构建：

1. 启动网站一次，自动建立表、初始30景点、22攻略、10美食和2个基础账号，然后停止网站。
2. 在这个新库依次执行sql/demo-community-20261026.sql、sql/completion-content-20261026.sql。前者创建演示用户及攻略评论，后者创建社区、路线及独立源行程；空库缺少早期南阳基础路线时会补充该示例，最终每城2条、共10条。昵称与文案调整已合并到第一份脚本，不再额外执行旧修订脚本。
3. 再次启动，让全文搜索与新源行程版本基线完成初始化。

已有上一轮16账号的库，只需备份后执行completion-content-20261026.sql，再运行新版程序。脚本核对编号与名称，冲突时回滚；已有景点不覆盖人工文案，仅补充新初始景点尚未填充的默认主题/时长/图集。迁移标记保证重复执行不增加帖子、回复、路线或源行程，也不会在启动时重建被删除的社区内容。

SQLite脚本应在支持完整事务的SQLite工具中执行。完整表结构在sql/schema.sql，应用启动使用src/main/resources/schema.sql及触发器资源。构建与运行见README.md。
